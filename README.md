# APNsRoute

`Generated by ChatGPT 6.0 Astra.`

Release of the approved routing implementation for rootful iOS 14. Keeps your 13 domain/IP rules and `apnsroutectl doctor`, with no runtime logging. The working setup is iPhone SE (2020), iOS 14.8, unc0ver / Substitute 2.3.1 and Surge 5.5.3.

## Install or upgrade

Have Surge running, then install as root:

```sh
dpkg -i ./local.apnsroute_1.1.0_iphoneos-arm.deb
```

Installation **automatically enables APNsRoute and restarts apsd once**. No separate enable command is needed. This also applies to upgrades and reinstalls, including when the previous setting was disabled. The enabled setting persists across apsd restarts while jailbreak injection is active.

After apsd relaunches, check:

```sh
apnsroutectl doctor
```

Expect loaded package `1.1.0` and protocol `v16`; the diagnostic format has not changed. Check Surge's connection list and notification delivery on cellular. Doctor's latest matched sample may be an init connection or another rule match, so its ready state alone does not identify a courier connection.

If the setting is saved but the restart cannot complete, the installer prints recovery instructions: run `apnsroutectl restart`, then doctor after relaunch. A setting-write failure is reported as a configuration failure. Installation never loops or repeatedly terminates apsd.

You can close the terminal afterward; the tweak runs inside apsd.

## Controls and diagnostics

| Command | Action |
| --- | --- |
| `apnsroutectl doctor` | Read loading, routing and connection diagnostics. |
| `apnsroutectl status` | Show the saved setting. |
| `apnsroutectl disable` | Save native-routing mode and restart apsd once; diagnostics remain available. |
| `apnsroutectl enable` | Save enabled mode and restart apsd once. |
| `apnsroutectl restart` | Restart apsd with the saved setting. |

Doctor is the only diagnostic command. It does not change routing, restart apsd or send network probes. File and unified logging remain absent. `logs` and `observe` are unsupported commands. A manual disable stays in effect until you enable it or install/reconfigure the package again.

The independent socket snapshot shows up to 16 readable apsd TCP sockets on any port, with destination CIDR-match status. It has no hostname metadata, so `CIDR-match=no` does not exclude a domain match. BSD sockets do not cover every Network.framework/Nexus flow.

## Matching

These built-in rules are alternatives: **a domain match OR a destination IP match qualifies a request**, regardless of destination port.

```text
DOMAIN,identity.apple.com
DOMAIN-SUFFIX,push.apple.com
DOMAIN-SUFFIX,akadns.net
DOMAIN-KEYWORD,apple.com.edgekey.net
IP-CIDR,17.249.0.0/16
IP-CIDR,17.252.0.0/16
IP-CIDR,17.57.144.0/22
IP-CIDR,17.188.128.0/18
IP-CIDR,17.188.20.0/23
IP-CIDR6,2620:149:a44::/48
IP-CIDR6,2403:300:a42::/48
IP-CIDR6,2403:300:a51::/48
IP-CIDR6,2a01:b740:a42::/48
```

| Rule | Matching behavior |
| --- | --- |
| DOMAIN | Exactly `identity.apple.com`; its subdomains do not qualify through this rule. |
| DOMAIN-SUFFIX | The named domain itself and all its subdomains, with a dot boundary. |
| DOMAIN-KEYWORD | The literal substring anywhere in the hostname, including before or after other text. |
| IP-CIDR / IP-CIDR6 | The available destination address falls within any listed prefix. |

Hostname matching ignores ASCII case and one trailing DNS root dot. DNS hostname length/label validation remains. IPv4-mapped IPv6 addresses use the embedded IPv4 address. Unlisted IPv6/NAT64 prefixes are not inferred.

`init.push.apple.com`, every other valid hostname under `push.apple.com`, and matching addresses on other TCP ports are now eligible. An unrelated address on port 5223 no longer qualifies just because of its port. A matching IP can qualify when the hostname is absent or does not match, and a matching hostname does not require a listed IP.

The tweak remains scoped to **outgoing TCP requests from apsd** (unspecified protocol metadata is also eligible). Other processes and known non-TCP, listener or inbound requests keep their existing behavior. Matching reads endpoint/NECP metadata already available at the hook: it does not resolve DNS, walk CNAME chains, reverse-resolve IPs or inspect packet contents. A rule cannot match metadata that is not yet available.

APNsRoute requests capture by the active tunnel. Surge's own policy still determines how captured traffic is handled.

## Routing and validation

Eligible requests receive a copied NECP input with an explicit binding to the unique usable utun. Only the exact Cellular / Internet required-agent pair becomes a preference; its value bytes stay intact. Every original interface prohibition remains and is checked against the tunnel and its delegates. Conflicts, unavailable checks, unrelated constraints, ambiguous tunnels and malformed or conflicting address metadata keep the original request.

The selected utun is not authenticated as Surge-owned; use Surge as the active VPN. Interface checks are momentary observations. The NECP request/result pair and public Network samples are independent, and neither alone establishes capture or notification delivery.

Routing and diagnostic behavior are retained from the approved experimental17 source. Host regressions, staged installation/upgrade and failure cases, cross-build, package/signature verification and archive checks passed. This release package has not been remotely installed on your phone. Nine known legacy arm64e ABI linker warnings remain from the same toolchain. The source archive contains the installer, tests, checksums and detailed notes.
