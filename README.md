# APNsRoute

`Generated by ChatGPT 6.0 Astra`

APNsRoute routes matching outgoing apsd TCP requests through the active VPN tunnel and retires old connection endpoints after Wi-Fi/cellular switches. Version 1.2.0 promotes the working experimental6 behavior with code cleanup, automatic enablement and `apnsroutectl doctor` retained.

The tested setup is **iPhone SE (2020), iOS 14.8, unc0ver / Substitute 2.3.1, Surge 5.5.3**. The package targets rootful iOS 14. The latest user test kept the same apsd process through cellular → Wi-Fi → cellular, replaced the old couriers and reported no crash. See VALIDATION.md for the observations and their scope.

## Install or upgrade

Keep Surge running and install as root:

```sh
dpkg -i ./local.apnsroute_1.2.0_iphoneos-arm.deb
```

Installation **enables the tweak and requests one apsd reload**. No separate enable command is needed. Fresh installs, upgrades and reinstalls all enable it. Later ordinary apsd starts honor the saved setting, including a manual disable. After the installation reload:

```sh
apnsroutectl doctor
```

Expect loaded package `1.2.0`, protocol `v22` and nine hook trampolines. You can close the terminal afterward. If installation cannot reload apsd, follow its printed instructions; a saved setting alone does not verify loading.

## Controls and saved setting

| Command | Action |
| --- | --- |
| `apnsroutectl doctor` | Read loading, routing, handover and connection diagnostics. |
| `apnsroutectl status` | Show the saved setting. |
| `apnsroutectl enable` | Save enabled mode and restart apsd once. |
| `apnsroutectl disable` | Save native routing/lifetime and restart apsd once; diagnostics remain available. |
| `apnsroutectl restart` | Restart apsd with the saved setting. |

The setting is stored at `/Library/Application Support/APNsRoute/mode`. `unbind` means enabled; `disabled` means native routing/lifetime. There is no additional settings file. The legacy saved value `observe` also selects native behavior, but the `observe` command is unsupported.

Doctor is the only diagnostic command. It does not restart apsd, change routing, write logs or send network probes. Runtime file/unified logging and the `logs` command are absent.

## Handover behavior

The first satisfied Wi-Fi or cellular observation establishes a baseline and closes nothing. A later change between those network types marks previously established, tracked matching connections for retirement, including cellular spares opened while Wi-Fi was active.

A **three-second window** allows an earlier request when a fresh matched connection receives nonempty, successful data on the current physical network. At the deadline, or on that earlier evidence, APNsRoute calls public `nw_connection_cancel_current_endpoint`. The framework can advance to another endpoint or report failure; CFNetwork/apsd receives the native callbacks and decides how to recover. New connections first reaching readiness in the new generation are protected.

The tweak keeps an awaiting flag until native readiness, terminal state or owner cleanup is observed. It makes no duplicate request while awaiting, even if networks change again. If the same Network.framework object becomes ready after endpoint fallback, it is tracked for later switches. An unchanged doctor object ID alone does not identify reuse of the old TCP/Surge transport.

Automatic handover handling does not restart apsd or inject new create/start/send/receive operations. Owner-requested normal cancellations still use the existing immediate-teardown dispatch. Natural recovery may create initialization sessions and unsuccessful secondary courier attempts; those occurred in the successful test. Brief reconnection delays remain possible.

Unknown, mixed or unsatisfied monitor paths suspend new requests. Tracking is bounded to eight matched objects with usable state handlers. Missing endpoint capability disables automatic retirement while retaining existing routing. No full-connection cancellation fallback is used for automatic retirement. An unanswered endpoint request remains visible in doctor.

## Read doctor output

| Field | Meaning |
| --- | --- |
| apsd PID / loaded package | Identifies the running process and loaded build. A PID change resets per-process observations. |
| Monitor network / generation | Observed Wi-Fi/cellular path and transition generation. |
| Held / older pending | Tracked objects and older objects awaiting their first retirement request. |
| Endpoint retirement requests | Number of automatic endpoint API calls, globally and per object. |
| Awaiting native readiness/closure | Requested objects without an observed native response or owner cleanup. |
| Connection # / handler # | Local NW object and handler IDs; not verified Surge row IDs. |
| State / history / last error | Native callback observations; successful callbacks do not erase earlier errors. |
| Send / receive / bytes | apsd API calls and aggregate received sizes. Payloads are not inspected or saved. |
| Complete callbacks | Original content/message completion flag, not necessarily TCP EOF. |
| Cancels: normal / force | Calls made by the owner; upgraded normal calls stay in the normal column. |
| Path | Sample at the last intercepted receive-registration or cancellation call, not a live poll. |

The eight diagnostic rows are bounded observations. Empty slots are used first, then terminal/cleared rows can be reused. New creates at reused addresses receive new scalar IDs; late callbacks cannot overwrite replacements. Missing creations, missing endpoint metadata and capacity limit coverage. Diagnostic rows own no connection references; the separate retirement registry owns at most eight.

For a handover check, keep the same apsd process through cellular → Wi-Fi → cellular and run doctor at each stage after allowing recovery. Inspect monitor generation, request and awaiting counts, then verify old-entry closure in Surge and a newly delivered notification. A request count or zero pending count alone does not establish success; natural closure, tracking skips and unavailable monitoring also affect those values.

NECP request/result samples and NW rows are independent. The socket snapshot shows at most 16 readable TCP sockets on any port, with destination CIDR annotation; it cannot see all Network.framework/Nexus flows or supply hostname metadata.

## Matching

These built-in rules are alternatives: **a domain match OR a destination IP match qualifies a request**, regardless of destination port.

```text
DOMAIN,identity.apple.com
DOMAIN-SUFFIX,push.apple.com
DOMAIN-SUFFIX,akadns.net
DOMAIN-KEYWORD,apple.com.edgekey.net
IP-CIDR,17.249.0.0/16
IP-CIDR,17.252.0.0/16
IP-CIDR,17.57.144.0/22
IP-CIDR,17.188.128.0/18
IP-CIDR,17.188.20.0/23
IP-CIDR6,2620:149:a44::/48
IP-CIDR6,2403:300:a42::/48
IP-CIDR6,2403:300:a51::/48
IP-CIDR6,2a01:b740:a42::/48
```

| Rule | Matching behavior |
| --- | --- |
| DOMAIN | Exactly `identity.apple.com`; its subdomains do not qualify through this rule. |
| DOMAIN-SUFFIX | The named domain itself and all its subdomains, with a dot boundary. |
| DOMAIN-KEYWORD | The literal substring anywhere in the hostname, including before or after other text. |
| IP-CIDR / IP-CIDR6 | The available destination address falls within any listed prefix. |

Hostname matching ignores ASCII case and one trailing DNS root dot. DNS hostname length/label validation remains. IPv4-mapped IPv6 addresses use the embedded IPv4 address. Unlisted IPv6/NAT64 prefixes are not inferred.

`init.push.apple.com`, every other valid hostname under `push.apple.com`, and matching addresses on other TCP ports are eligible. An unrelated address on port 5223 does not qualify just because of its port. A matching IP can qualify when the hostname is absent or does not match, and a matching hostname does not require a listed IP.

The tweak remains scoped to **outgoing TCP requests from apsd** (unspecified protocol metadata is also eligible). Other processes and known non-TCP, listener or inbound requests keep their existing behavior. Matching reads endpoint/NECP metadata already available at the hook: it does not resolve DNS, walk CNAME chains, reverse-resolve IPs or inspect packet contents. A rule cannot match metadata that is not yet available.

APNsRoute requests capture by the active tunnel. Surge's own policy still determines how captured traffic is handled.

## Routing contract

Eligible requests receive a copied NECP ADD input with an explicit binding to the unique usable utun. Only the exact Cellular / Internet required-agent pair becomes a preference; its value bytes remain intact. Original interface prohibitions are preserved and checked against the tunnel and delegates. Conflicts, unavailable checks, unrelated constraints, ambiguous tunnels and malformed/conflicting address metadata keep the native request. Returned kernel bytes remain unchanged.

The selected utun is not authenticated as Surge-owned; use Surge as the active VPN. Its rules determine how captured traffic is handled. Tunnel checks are momentary observations, and matching uses only metadata already available to the hooks.

## Release validation and recovery

The cleanup clarifies lifecycle state names, centralizes reference transfer and removes an unused include. Matching, endpoint API choice, timing, callback forwarding, capacity and routing guards retain the experimental6 behavior. Protocol v22 retains all 185 diagnostic fields; release 1.2.0 has its own build identity.

Host regressions, lifecycle sanitizer checks, the iOS cross-build and package/signature verification pass. PRESERVATION-REPORT.txt records compiler comparisons and the refactored module's review scope. Eleven known legacy arm64e ABI linker warnings remain with the cached toolchain. The new release binary has not been run remotely on the phone; the device confirmation applies to its experimental6 baseline and one reported round trip.

The source archive contains the unchanged working experimental6 installer under `rollback/`:

```sh
dpkg -i ./local.apnsroute_1.1.1~experimental6_iphoneos-arm.deb
```

Downgrading enables the saved mode and requests one reload, like installation. To remove the tweak:

```sh
dpkg -r local.apnsroute
killall -TERM apsd
```
