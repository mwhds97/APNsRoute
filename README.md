# APNsRoute 1.2.1

`Generated by ChatGPT 6.0 Astra`

APNsRoute routes matching outgoing apsd TCP requests through the active VPN tunnel. Wi-Fi/cellular changes and VPN on/off/replacement share **one two-second quiet period** before automatic endpoint cleanup. Further observed changes reset the same timer, grouping a proxy app's VPN restart with the physical-network switch.

The target is **iPhone SE (2020), iOS 14.8, unc0ver / Substitute 2.3.1, Surge 5.5.3**, using a rootful iOS 14 jailbreak. Version 1.2.1 promotes the tested experimental2 behavior. The supplied phone snapshots show grouped transitions and ready replacement couriers with the same apsd PID throughout each sequence. They do not independently measure the elapsed two-second interval or prove notification delivery. Automatic enablement and `apnsroutectl doctor` remain. The archive includes 1.2.0 and the tested experimental2 rollback installers.

## Install or upgrade

Keep Surge running and install as root:

```sh
dpkg -i ./local.apnsroute_1.2.1_iphoneos-arm.deb
```

Installation **enables the tweak and requests one apsd reload**. No separate enable command is needed. Fresh installs, upgrades and reinstalls all enable it. Later ordinary apsd starts honor the saved setting, including a manual disable. After the installation reload:

```sh
apnsroutectl doctor
```

Expect loaded package `1.2.1`, protocol `v24` and nine hook trampolines. You can close the terminal afterward. If installation cannot reload apsd, follow its printed instructions; a saved setting alone does not verify loading.

## Controls and saved setting

| Command | Action |
| --- | --- |
| `apnsroutectl doctor` | Read loading, routing, handover and connection diagnostics. |
| `apnsroutectl status` | Show the saved setting. |
| `apnsroutectl enable` | Save enabled mode and restart apsd once. |
| `apnsroutectl disable` | Save native routing/lifetime and restart apsd once; diagnostics remain available. |
| `apnsroutectl restart` | Restart apsd with the saved setting. |

The setting is stored at `/Library/Application Support/APNsRoute/mode`. `unbind` means enabled; `disabled` means native routing/lifetime. There is no additional settings file. The legacy saved value `observe` also selects native behavior, but the `observe` command is unsupported.

Doctor is the only diagnostic command. It does not restart apsd, change routing, write logs or send network probes. Runtime file/unified logging and the `logs` command are absent.

## Combined transition handling

A Wi-Fi/cellular change, VPN appearance/disappearance, or replacement of the active tunnel starts a **minimum two-second wait**. Any further observed transition resets the same deadline. For example:

| Time | Observed event | Earliest automatic cleanup |
| --- | --- | --- |
| 0.0 s | Cellular → Wi-Fi | 2.0 s |
| 0.4 s | VPN off | 2.4 s |
| 0.9 s | VPN on | 2.9 s |

No automatic endpoint request happens at the first two deadlines. When the last deadline is reached, one batch covers the eligible old tracked connections. Readiness, incoming traffic and already-queued work cannot bypass the quiet period. Scheduling can make the wait longer than two seconds. If native handling has already closed the old connections, there is no extra cleanup batch.

Unknown, mixed, unavailable or ambiguous observations suspend automatic cleanup. Returning to valid observations starts a fresh two-second wait. The first cold physical/VPN observations establish baselines and do not close anything. Repeated identical observations and successful data reception do not extend the deadline. A local tunnel snapshot is checked again immediately before cleanup; a newly discovered change postpones cleanup too.

This governs **APNsRoute's automatic requests**. iOS, apsd and the proxy app can still close their own connections while changing networks or shutting down VPN. The tweak does not hold back their callbacks or prevent a removed tunnel from disconnecting traffic.

## Which connections are affected

The scope remains the existing **13-rule apsd TCP traffic**, with up to eight tracked objects that have state handlers. It includes init, courier and other matching domains/IPs. Other apps' connections are not managed.

Objects established before a physical change are eligible. A physical connection still establishing is dated at first readiness, retaining the working physical-handover behavior. For VPN changes, start/request generations are retained: an older unfinished start becomes eligible on readiness, but still passes through the same quiet gate. A connection started after the last relevant observed change is kept. A start during the burst may become old if another VPN event follows it.

Each selected object receives one `nw_connection_cancel_current_endpoint` request in the batch. Native callbacks drive recovery. There is no automatic apsd restart, fabricated failure or terminal-cancel fallback. An object awaiting native recovery receives no duplicate request. If another VPN change occurs while it awaits, it may need one later request after readiness and the quiet gate; therefore a delayed native response can produce a later batch. An NW object ID may survive replacement of its TCP endpoint and is not a Surge row ID.

The detector samples local interfaces on network-change notifications, path-monitor updates and a one-second fallback timer; these checks send no packets. One up `utun` with a usable non-link-local IP is on, none is off, and a different name/index is replacement. Failed/ambiguous reads are not off. The tunnel is not authenticated as Surge-owned. A complete off/on returning to identical identity between all observations cannot be distinguished; detection and scheduling are best effort.

## Read doctor output

| Field | Meaning |
| --- | --- |
| apsd PID / loaded package | Identifies the running process and loaded build. A PID change resets per-process observations. |
| Shared quiet period | Idle, waiting or blocked by uncertain observations; remaining milliseconds are from the last runtime check, not a live doctor countdown. |
| Transition group / observations / causes | Events combined into the current or last group, including loss/recovery of valid observations. |
| Cleanup batches | Batches that actually submitted at least one endpoint request. It is separate from per-object request counts. |
| Monitor network / generation | Observed Wi-Fi/cellular path and transition generation. |
| VPN transition monitoring / generation | Validated tunnel state/index and its independent generation. First valid observation is generation 1. |
| Last VPN change / VPN endpoint requests | Latest observed on/off/replacement and the subset of requests caused by VPN transitions. |
| Connections from an older VPN generation | Old tracked objects, including not-yet-ready or still-recovering objects that need cleanup. |
| Network-change notifications | Subscription status. Periodic local checks still run if registration fails. |
| Held / older pending | Tracked objects and established objects eligible by physical or VPN age and not already awaiting recovery. |
| Endpoint retirement requests | Number of automatic endpoint API calls, globally and per object. |
| Awaiting native readiness/closure | Requested objects without an observed native response or owner cleanup. |
| Connection # / handler # | Local NW object and handler IDs; not verified Surge row IDs. |
| State / history / last error | Native callback observations; successful callbacks do not erase earlier errors. |
| Send / receive / bytes | apsd API calls and aggregate received sizes. Payloads are not inspected or saved. |
| Complete callbacks | Original content/message completion flag, not necessarily TCP EOF. |
| Cancels: normal / force | Calls made by the owner; upgraded normal calls stay in the normal column. |
| Path | Sample at the last intercepted receive-registration or cancellation call, not a live poll. |

The eight diagnostic rows are bounded observations. Empty slots are used first, then terminal/cleared rows can be reused. New creates at reused addresses receive new scalar IDs; late callbacks cannot overwrite replacements. Missing creations, missing endpoint metadata and capacity limit coverage. Diagnostic rows own no connection references; the separate retirement registry owns at most eight.

For a handover check, keep the same apsd process through cellular → Wi-Fi → cellular and run doctor at each stage after allowing recovery. Inspect monitor generation, request and awaiting counts, then verify old-entry closure in Surge and a newly delivered notification. A request count or zero pending count alone does not establish success; natural closure, tracking skips and unavailable monitoring also affect those values.

NECP request/result samples and NW rows are independent. The socket snapshot shows at most 16 readable TCP sockets on any port, with destination CIDR annotation; it cannot see all Network.framework/Nexus flows or supply hostname metadata.

## Matching

These built-in rules are alternatives: **a domain match OR a destination IP match qualifies a request**, regardless of destination port.

```text
DOMAIN,identity.apple.com
DOMAIN-SUFFIX,push.apple.com
DOMAIN-SUFFIX,akadns.net
DOMAIN-KEYWORD,apple.com.edgekey.net
IP-CIDR,17.249.0.0/16
IP-CIDR,17.252.0.0/16
IP-CIDR,17.57.144.0/22
IP-CIDR,17.188.128.0/18
IP-CIDR,17.188.20.0/23
IP-CIDR6,2620:149:a44::/48
IP-CIDR6,2403:300:a42::/48
IP-CIDR6,2403:300:a51::/48
IP-CIDR6,2a01:b740:a42::/48
```

| Rule | Matching behavior |
| --- | --- |
| DOMAIN | Exactly `identity.apple.com`; its subdomains do not qualify through this rule. |
| DOMAIN-SUFFIX | The named domain itself and all its subdomains, with a dot boundary. |
| DOMAIN-KEYWORD | The literal substring anywhere in the hostname, including before or after other text. |
| IP-CIDR / IP-CIDR6 | The available destination address falls within any listed prefix. |

Hostname matching ignores ASCII case and one trailing DNS root dot. DNS hostname length/label validation remains. IPv4-mapped IPv6 addresses use the embedded IPv4 address. Unlisted IPv6/NAT64 prefixes are not inferred.

`init.push.apple.com`, every other valid hostname under `push.apple.com`, and matching addresses on other TCP ports are eligible. An unrelated address on port 5223 does not qualify just because of its port. A matching IP can qualify when the hostname is absent or does not match, and a matching hostname does not require a listed IP.

The tweak remains scoped to **outgoing TCP requests from apsd** (unspecified protocol metadata is also eligible). Other processes and known non-TCP, listener or inbound requests keep their existing behavior. Matching reads endpoint/NECP metadata already available at the hook: it does not resolve DNS, walk CNAME chains, reverse-resolve IPs or inspect packet contents. A rule cannot match metadata that is not yet available.

APNsRoute requests capture by the active tunnel. Surge's own policy still determines how captured traffic is handled.

## Routing contract

Eligible requests receive a copied NECP ADD input with an explicit binding to the unique usable utun. Only the exact Cellular / Internet required-agent pair becomes a preference; its value bytes remain intact. Original interface prohibitions are preserved and checked against the tunnel and delegates. Conflicts, unavailable checks, unrelated constraints, ambiguous tunnels and malformed/conflicting address metadata keep the native request. Returned kernel bytes remain unchanged.

The selected utun is not authenticated as Surge-owned; use Surge as the active VPN. Its rules determine how captured traffic is handled. Tunnel checks are momentary observations, and matching uses only metadata already available to the hooks.

## Verify after upgrading

After installation, run `apnsroutectl doctor`. Expect package `1.2.1`, protocol v24 and the **Shared quiet period** and **cleanup batches** lines.

Keep the same apsd process during these checks:

1. Switch cellular → Wi-Fi and allow Surge's automatic VPN off/on sequence to finish. Wait at least two seconds after the final transition, then run doctor. Compare transition-group observations and batch/request counts with the before snapshot.
2. Switch back to cellular and repeat. Verify old Surge entries close and a new notification arrives.
3. On the same physical network, test a standalone VPN off and on, allowing each to settle; then try off/on less than two seconds apart. The short burst should not cause separate immediate APNsRoute cleanup calls for each event.

Use Surge's controls for the VPN test. `apnsroutectl enable` and `disable` control the tweak and restart apsd, resetting the evidence. The apsd PID should stay unchanged during the test. Natural closure can remove objects before cleanup; delayed readiness/recovery can require later work. Thus batch/request counts are evidence of the tweak's actions, not a guaranteed count of transport closures or notifications. If behavior differs, send doctor snapshots before and after the sequence.

Host regressions, lifecycle ASan/UBSan checks, the iOS cross-build and package/signature verification pass. Tests include the exact three-event example above, sub-millisecond deadline boundaries, stale timers/work, missed VPN hints, native recovery and reference ownership. The release keeps the tested transition policy and centralizes its duration constant so the runtime and doctor display agree. The known legacy arm64e build warnings remain. See VALIDATION.md for the phone evidence, test scope and compiler details, and CHANGE-REVIEW.md for the release cleanup.

## Rollback or removal

The source archive includes unchanged **1.2.0** and **1.2.1~experimental2** installers under `rollback/`. To return to the previous stable release:

```sh
dpkg -i ./local.apnsroute_1.2.0_iphoneos-arm.deb
```

Downgrading enables the saved mode and requests one reload, like installation. To remove the tweak:

```sh
dpkg -r local.apnsroute
killall -TERM apsd
```
